# webgpu-context-ceiling

> WebGPU Qwen ctx ceiling: 7168 cap REMOVED (streaming split-KV decode attn, cap now 16384), blank-turn bug + fix, path to 32K

_Design note written during development (sandpie session memory); names like `TabInfer*` refer to the pre-extraction identifiers, now `TabInfer*`._

**The 7168-token context cap is OURS, not Qwen's.** Qwen3-0.6B natively supports 32K (40K w/ YaRN). The cap = the DECODE attention kernel (attnDecWgsl, T=1) storing ALL key-scores in workgroup memory: `var<workgroup> sc: array<f32, MAXS>`, MAXS = (maxComputeWorkgroupStorageSize − 4096)/4 = (32768−4096)/4 = **7168** on gen-12lp (32KB workgroup storage). `_ctxCap = min(_attnMaxS=7168, provider.contextWindow)` → setting contextWindow=8192 is silently clamped to 7168. Prefill attention streams K/V in tiles (online softmax, no full-score array) so it has NO such cap — only decode does.

**"Model only thinks then stops, empty message" bug (FIXED, commit 6f6275c):** in multi-turn with a large tool result kept verbatim (e.g. a 22KB `dir` listing ≈ 6.5K tokens), the prompt sits near 7168. decodeLoop caps generation at MAX_SEQ−1−pos. Measured: prompt=6750 tok → only ~417 tokens of generation budget; decode=310 → JUST finished. A slightly bigger history drops budget below the model's ~300-token `<think>` length → decode hits the cap BEFORE closing `</think>` → makeRoundParser stuck in 'think' state, content empty, no tool call → conversations.js rendered a SILENT BLANK turn. (Worsens each turn as history grows. The +1024 gen-headroom `_streamIds` requests is clamped by _ctxCap, so it can't be reserved away within the ceiling.) FIX: runConversation now never leaves a blank turn — when a round yields no content AND no tool_calls, it emits an actionable ⚠️ message ("near the model's <_ctxCap>-token limit; start a new chat / remove a large earlier message / raise Context size"). makeRoundParser exposes `get state()` (='think' ⇒ cut mid-think). Guard fires ONLY when both content+toolCalls empty → normal answers/tool calls untouched (verified maxTokens=30 forces it → warning shown; coherent gen + tool calls still work). The OTHER mode (L>7168) already throws a clear "prompt too long: N tokens — exceeds 7168" error (not blank).

**UPDATE 2026-07-02 (commit e710914): job (1) DONE — streaming split-KV decode attention shipped.** attnDecStreamWgsl: online softmax over 128-key tiles (sc array = one tile, O(1) in S) + split-KV (nsplit = ceil(S/640) clamped 16 workgroups/head emit unnormalized m/l/o partials; exact combine pass). HYBRID dispatch: legacy kernel kept for S≤640 (streaming's combine pass = 0.84× there) and behind __noStreamDecAttn; streaming for S>640. Warm GPU-timestamp A/B (_benchAttnDec, min-of-8): 1.18× @1024, 1.11× @2048, 1.02-1.07× @2688-7168 — modest speed win, the REAL win = ceiling removed, _attnMaxS now DEC_STREAM_CTX=16384 (KV f32 memory budget). Methodology reconfirmed: cold/idle-GPU benches inflate deltas (1.23× cold → 1.07× warm); focused-tab main-thread E2E tok/s swings 3× within the same variant — trust only warm GPU timestamps. Pre-existing marginal: attentionTiled selfTest (f16 prefill) 3.6e-3 vs 2e-3 tol, passes on f32 path.

**UPDATE 2026-07-02 later (commit 0efd16d): job (2) DONE — int8 KV cache shipped, cap now 32768.** KV = per-32-group snorm int8 (pack4x8snorm; u32 words + f32 group scales; 1.125B/elem, 3.5× smaller). attnDecStreamQ8 (scales hoisted out of dot inner loop): isolated warm GPU-ts 1.71× @2688 / 1.97× @7168 over f32 streaming. Q8 prefill variants string-transformed from ATTN_WGSL/attnF16Wgsl (dequant only in tile-load; costs 2% at chunked shape). kvQuantWrite = one dispatch/layer REPLACING the two KV copyRange copies (key difference from the failed f16 bolt-on: no extra passes). int8 rides streaming only — __noKvQ8/__noStreamDecAttn revert to f32+hybrid. E2E: 18.6 vs 11.4 tok/s @2.6K prompt (both coherent/correct); 9.2K prompt prefills 89s, decodes 4.5 tok/s coherent. GOTCHA found: generate() (test-page path) didn't grow/chunk prefill → >MAX_SEQ prompt = silent KV OOB garbage ("!"); fixed to mirror _streamIds. Synthetic-periodic bench data inflates int8 quant error (softmax near-ties: 0.3 rel!) — decorrelated data shows the true ~4e-3; don't trust periodic fixtures for quant-quality judgments. Qwen3-0.6B KV = 28L×8kvH×128×2 = 57344 f32/token. KV totals: 8K f32=1.88GB, 16K f16=**1.88GB (feasible)**, 32K f32=7.52GB (infeasible), 32K f16=3.76GB (tight). This iGPU maxBufferSize/maxStorageBinding = 2.15GB (per-buffer; KV is per-layer so per-buffer is fine, but TOTAL 7.5GB f32 @32K is not). So: streaming decode + f16 KV → 16K comfortable, ~24K possible, 32K memory-tight on this laptop iGPU. f16 KV must be folded INTO the streaming kernel (bolting f16 onto the current decode kernel regressed 12× — see [[reference_llamacpp-webgpu-decode-paths]]). Related: [[reference_litert_mldrift_gpu_techniques]] (f16 prefill attention already shipped, 2× kernel / +35% prefill).

**UPDATE 2026-07-02 (commit 8523656): "Context size doesn't propagate" bug FIXED.** User set contextWindow=8192, still died mid-`<think>` at ~4096 with the ⚠️ message quoting 8192. Cause: _ctxCap propagated fine but is only a growth CEILING — the allocated KV window MAX_SEQ (default 4096) only grew on PROMPT overflow (`L+64>MAX_SEQ`), never for decode headroom, and decodeLoop hard-stops at MAX_SEQ−1−pos. Fix in _streamIds + generate(): grow to `L + 64 + min(maxTokens,_ctxCap)` capped at _ctxCap, rounded up to 1K steps (per-turn L creep must not force a KV realloc every turn — _growCtx drops the prefix cache = full re-prefill); prompt-too-long check now against _ctxCap directly; runConversation default maxTokens resolved AFTER loadModel from _ctxCap (was captured from stale pre-load MAX_SEQ=4096, silently capping output at 4096 tokens).
